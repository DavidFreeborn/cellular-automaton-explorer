Cellular Automaton Explorer

What is a Cellular Automaton?

A cellular automaton is a computational model consisting of a grid of cells, each in one of a finite number of states. At each time step, every cell updates its state based on a simple rule that considers the cell and its neighbors.

This simulator explores one-dimensional elementary cellular automata, where each cell looks at itself and its two neighbors (left and right) to determine its next state. Time flows downward, with each row showing a new generation.

How Rules Work

Each rule is identified by a number from 0 to 255. The rule number encodes what happens for each of the 8 possible neighborhood patterns (3 cells = 2³ = 8 patterns). The binary representation of the rule number directly specifies the output for each pattern.

For example, Rule 110 = 01101110 in binary. Reading right to left, this means:

  • Pattern 000 (all dead) produces 0 (stays dead)
  • Pattern 001 produces 1 (becomes alive)
  • Pattern 010 produces 1, and so on...

Boundary Conditions

Since our grid is finite, we need rules for what happens at the edges:

Periodic

The grid wraps around like a cylinder. The leftmost cell's left neighbor is the rightmost cell. This eliminates edge effects entirely.

Fixed (dead)

Cells outside the boundary are always 0. Patterns interact with empty space at the edges.

Fixed (alive)

Cells outside the boundary are always 1. Patterns interact with a wall of live cells.

Reflective

Edge cells are mirrored, as if there's a reflecting surface at the boundary.

Notable Rules to Explore

Rule 110 (Recommended starting point)
Proven Turing complete by Matthew Cook in 2004. This means it can simulate any computation given the right initial conditions. Watch for 'gliders' - persistent structures that move across the grid.

Rule 30 (Chaotic)
Produces chaotic, seemingly random patterns from a single cell. Used by Mathematica as a random number generator. The center column passes statistical randomness tests.

Rule 90 (Fractal)
Creates the famous Sierpinski triangle fractal. Each cell is the XOR of its two neighbors, connecting to Pascal's triangle modulo 2.

Rule 184 (Traffic flow)
Models traffic flow: cells (cars) move right if the space ahead is empty. Try random initial conditions to see congestion patterns emerge.

Tips for Exploration

  • Start with a single cell to see the 'natural' pattern of each rule
  • Try random initial conditions to see how rules handle noise
  • Compare periodic vs fixed boundary conditions
  • Use comparison mode to see two rules side by side
  • Watch for: gliders, fractals, chaos, periodic patterns, and stable structures
